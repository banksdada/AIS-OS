# Hosting Health Report — Scope

**Date:** 2026-10-23 · **Status:** planned · **Owner:** Banks Dada
**Goal:** Give the £50–£60 hosting renewal a tangible reason to renew, so clients who stopped believing they need a website still pay.

## The problem

~4–5 clients renew per year, ~4–5 lapse. Most clients stop seeing a need for a website after ~1 year and don't renew. The reminder script already exists and works — but it only asks for money. It delivers nothing *to* the client, so there's no reason to say yes.

## The fix

Every year, at renewal time, each client gets a **website health report** — a plain-language document showing what's been looked after, what's healthy, and what needs attention. The report is the reason to renew; the reminder email is the delivery vehicle.

## What the report contains

1. **Uptime & availability** — was the site up all year? Any outages, and how long?
2. **Security** — CMS/core/plugin updates current or behind? SSL certificate valid and not near expiry? Any known vulnerabilities?
3. **Backups** — last successful backup date, retention, and that a restore has been verified.
4. **Performance** — page load time, mobile friendliness, any slow pages.
5. **SEO basics** — indexation status, broken links, what's changed in search visibility this year.
6. **What changed this year** — a short, honest summary of the work done on the site (patches, fixes, content added).
7. **Recommendations** — 2–3 things worth doing next year, with plain-language reasons.

## What ecoWebhosting actually exposes (checked 2026-10-23)

The help centre at https://help.ecowebhosting.co.uk/ was reviewed. Findings that change the plan:

- **No API.** No REST API, WHM/cPanel API, or DirectAdmin API is documented or offered. Everything is done through the control panel and the client area. **Any health data must be gathered by probing the live site, not by querying the host.**
- **Control panel** (identity unconfirmed — cPanel-style, given cpGuard + JetBackup): File Manager, FTP/SSH, databases, cron, free SSL, Softaculous WordPress manager, LiteSpeed + Redis, Git, PHP version selector, Node.js/Python.
- **Backups are JetBackup**, automated (daily or weekly depending on plan), retained for a defined period, and restorable via the control panel. **There is no programmatic way to read "last successful backup date"** — the report can only say backups are configured per the plan, and mark it *not independently verified*.
- **No uptime monitoring** offered by the host. Uptime data must come from the script's own HTTP probes.
- **Free SSL** for all domains, managed by the host — cert expiry is checkable directly via TLS handshake (stdlib `ssl` module), which is the one check with a real, verifiable number.

**Net effect:** the report is built almost entirely from probing the client's live website plus the WordPress REST API. The host contributes nothing queryable. That's fine — it also means the report is genuinely *independent* of what the host claims.

## How it works

**Option A (recommended) — automated, generated by the reminder script.**
Extend `scripts/pyrunner/hosting-renewal-reminders.py` to produce the report per client and attach it to the renewal email (HTML body + PDF attachment). Sources: WordPress REST API for CMS/SEO data, direct HTTP probe for uptime/performance, stdlib `ssl` for cert expiry. The script already reads a sheet of clients and sends email — this is an addition, not a rewrite.

**Option B — human-reviewed.**
Banks reads and annotates each report before sending. Higher trust, but it's the same admin he's trying to cut. Only worth it for the first 12 months or for high-value clients.

## The renewal email changes

Instead of "your hosting renews, please pay", it becomes:

> "Here's your annual website health report for [site]. It shows your site was up 30/30 days this month, your SSL is valid, and your last backup was [date]. Here's what we did for it this year: [summary]. Your renewal of £55 is due on [date]. The full report is attached. Reply with any questions."

The *report is the product*. Payment is the obvious next step.

## Out of scope (for now)

- Charging extra for the report (that's the re-price to a managed plan — do this after proving it reduces churn)
- Referral programme, second-product upsell, CRM churn tracking
- Migrating off ecoWebhosting or changing the reseller agreement

## Risks

- **Data quality.** A report with wrong numbers is worse than no report. Test on 2–3 clients first and fix before batch.
- **Banks's time.** Option A must be genuinely automated, or this just moves the admin around. If any step needs manual intervention, it's not solved.
- **Over-promising.** The report must not claim a restore was tested if it wasn't. Be honest about what's verified vs assumed.
- **ecoWebhosting has no API**, so every data point comes from probing the live site. That's slower and less complete than a host API — say so plainly in the report rather than implying a deeper check.
