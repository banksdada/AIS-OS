# Content brain interview

Interview the user one question at a time about five topics, then save each topic as one file. The answers become the real material every post draws on.

Source: Sabrina Ramonov, "Content Systems on Autopilot". The "invent nothing" rule is hers and is the most important one here.

## The five topics

| File | What it captures |
|---|---|
| `audience.md` | Who the posts are for, their job, their problem, what they search for |
| `beliefs.md` | Opinions the user holds that others may disagree with |
| `stories.md` | Real experiences: what happened, what they did, what changed |
| `proof.md` | Results, numbers, clients, projects, things the user can show |
| `voice.md` | How they talk: sentence length, words they use, words they avoid |

Save these under `brain/` inside the topic's folder (see `content-system`). For Banks's LinkedIn work, the voice samples in AGENTS.md → Voice are the starting point for `voice.md`; do not overwrite them.

## How to run it

1. Ask **one question at a time.** Wait for the answer before the next.
2. After each answer, save it to the right file straight away. Don't batch.
3. Ask for an example after any abstract answer ("Give me one real time that happened"). Stories are the value; generalities are not.
4. Stop when the user says so, or when a topic has enough real material to draft from. Summarise what each file now holds and what is still thin.

## Rules

- **Invent nothing.** If the user doesn't have a story, record that there isn't one. Never write a plausible anecdote, number, client name or quote.
- **Keep identifying details out of stories** unless the user confirms they're happy to share them. Use "a client" or "a UK agency" by default. This matters for anything client-facing.
- **Confirm before saving anything sensitive** (client names, money, personal health or family).
- **Mark the date** on each entry, so old answers can be seen as old.
- **Don't overwrite.** Append new answers under a dated heading. Edit only when the user corrects something.

## Output

After a session: which files changed, how many real stories are now in `stories.md`, and the one topic that is still thin. Keep it to a few lines.
